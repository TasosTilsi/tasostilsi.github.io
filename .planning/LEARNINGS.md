### Lessons

- A Next.js App Router route rename cannot be split across commits: while both `src/app/(main)/page.tsx` and `src/app/(home)/page.tsx` exist there are two providers of `/` and `next build` fails. The route move + all link rewires landed as ONE atomic task, and the plan accepted a 15-file scope (above the <=10 heuristic) rather than break the build between commits. Next time, budget the whole blast radius as one unit; the file-count heuristic is wrong for route renames. (source: PLAN-01#objective 'Why the implementation is one unit' + RESEARCH#R-1)
- TDD at export level only works if the build runs BEFORE the red run. `rm -rf out && npm run build && node --test …` was the pinned red command specifically so the export rows fail on the missing contract (no `out/cli.html`, stale `explore.html`) instead of on a missing `out/` directory. Without the pre-build, the red output is unreadable and cannot be distinguished from a broken environment. (source: PLAN-01#task-1 acceptance_criteria 3rd bullet + SUMMARY-01#task-1-red)
- Mechanical enumeration of stale route literals is not sufficient — the plan-checker's BLOCKER-1/BLOCKER-2 found live pins the enumeration missed: a test TITLE and a LIVE REGEX in `tests/explore-header.test.mjs` (`/<Link\b[^>]*?href="\/"/`) plus a `block.includes('<Link href="/explore"')` literal inside the CLI@375 sweep row. Three sites (reader path, test title, failure message) must each be renewed independently, and the fix must be tightening (href regex) not deletion. (source: PLAN-01#merge-hold (checker BLOCKER-1/BLOCKER-2 additions) + SUMMARY-02#task-2)
- Renewing prose in a file whose source text is asserted verbatim by an existing test row is a collision, not a freebie: two of the new suite's raw-source rows went red because renewal comments named `{children}` and the metadata-base token. Fix the comments (the file already being edited), never soften the assertion — and check every new raw-text assertion against the comments you just rewrote. The same class was pre-empted on the chip by not writing the router-primitive import path into a comment. (source: SUMMARY-01#deviations D-4)
- Plan-authored grep predicates can be self-contradictory: plan 02 required `grep -rn 'out/explore.html' tests/` to return nothing while the same plan mandated adding `!existsSync(join(root,'out/explore.html'))` as the route-deletion falsifier. Prefer read-specific greps (`grep -n "read('out/explore") and never let a hygiene predicate outrank a required negative assertion. (source: SUMMARY-02#deviations DEV-4 + VERIFICATION#deviations D-3)
- Commit scope tokens must match what the gate actually parses. `tdd_audit` derives its scope as `${phase}-${plan}` from the plan numerics, i.e. it regexes `(12-01)` — the plan's pinned `test(phase-12): …` subject would have matched NO scope, the phase-10 pathology that previously forced `skip_gates: ["tdd_audit"]`. ### Patterns

- Two-tier, count-exact residue scan for a deleted route: assert ZERO hits in `out/*.html` + `out/*.txt` (the artifacts that must not name the dead path, including `404.html`) and `assert.equal(hits, 1)` across `out/_next/static/chunks/**` where the single hit is the named, accepted debt (the drawer's `~/explore`). A bare whole-tree zero was unreachable without violating the phase's do-not-touch constraint; a loose `> 0` would hide a second leak. Failure messages must name the offending paths. (source: PLAN-01#must_haves truth 4 + SUMMARY-01#residue-reconcile)
- When a test must prove a script is placed correctly but the value it keys on is single-sourced in a constants module, assert the IDENTIFIER and the BEHAVIOUR, never the string literal. The landing layout's theme script was proven by `EXPLORE_THEME_STORAGE_KEY` presence + the `/classList\.remove\(["']dark["'],\s*["']light["']\)/` pattern + `dangerouslySetInnerHTML` index ordering; the storage-key literal exists only at `constants.ts:34`, so a literal-grep would have been vacuous on both sides and a root-layout copy would have passed green. (source: SUMMARY-01#before-paint-proof + PLAN-01#task-1 row 4)
- Six-leg two-way composite in ONE test body: every cross-surface link (CLI→landing, landing→CLI, wizard finish, 404, chip) asserted both at source and in the built export within a single `test(...)`, so a half-rewire cannot pass. Applied independently in two suites (`route-swap` row 13, `explore-sweep` E-5). Any phase with more than two link sites should collapse them into one composite rather than per-site rows. (source: VERIFICATION#data-flow-trace + SUMMARY-02#six-leg-composite)
- Chrome constants in a zero-runtime-import plain-TS module let `node --test` import and assert VALUES directly instead of parsing JSX: `EXPLORE_STATUS_PATH`, `EXPLORE_STATUS_CLI_LINK` and `EXPLORE_TOUR_FINISH` were asserted by importing `constants.ts` natively (Node 24 strips types), so the assertion cannot drift from the render. Import as a NAMESPACE and destructure — a named import of a not-yet-existing symbol is a link-time SyntaxError that kills every row (invalid red). (source: PLAN-01#key_links L2/L6 + SUMMARY-01#task-1-red (namespace-import note))
- Explicit existence assertion BEFORE any `.filter(existsSync)` list. `tests/explore-shell.test.mjs` built its source list by filtering; after the route move the array silently dropped the page and the `!code.includes('h-screen')` guard degraded to checking one file. Repath AND harden: `assert.ok(existsSync(join(root, 'src/app/(home)/page.tsx')), 'landing page present — the h-screen guard must not silently degrade')`. A filtered list is a silent no-op generator. (source: SUMMARY-02#traps (P-1/R-4))
- Negative tripwire assertions to catch future config flips that would 404 the new route silently: assert `existsSync(out/cli.html)` AND `!existsSync(out/cli/index.html)`, so adding `trailingSlash` later fails loudly instead of quietly breaking every `/cli` href on GitHub Pages (no `trailingSlash` in `next.config.ts`; `out/resume.html` is the in-repo precedent). Pair every new route's positive artifact assertion with the wrong-shape negative. (source: SUMMARY-02#traps (R-8) + VERIFICATION#anti-patterns)
- Comment-only sweeps must be PROVEN comment-only: filter the commit's `git diff -U0` additions/removals against `^[+-]\s*(//|\*|/\*)` and require the non-comment diff to be empty (5 added / 5 removed lines, every added line a comment; `git diff --name-only HEAD -- src/app/globals.css` empty). Also drop dangling decision-id prefixes when renewing a plan's prose into a file whose phase-ids differ (the `D-04:` prefix belonged to phase 01, not this phase). (source: SUMMARY-02#comment-only-proof)
- Declared merge hold as durable state: record the branch as knowingly RED with the exact failing-suite inventory and the precise lift condition ('must NOT be merged, pushed, or handed off as green until plan 02's `npm run build && node --test tests/*.test.mjs` full-suite run is on record'), then lift it with the verbatim run. Phase-11 precedent, reused verbatim — it is what stops an intermediate per-plan green from being reported as phase green. (source: PLAN-01#merge-hold + SUMMARY-02#merge-hold-lifted)
- Green-gate finality ordering under a docs-carrying phase: run the gate after the last planning write AND re-run it post-commit (SWEEP Finality Run 1 + Run 2), because the run that predates the commit carrying the report cannot by itself cover the committed tree. Frozen precondition measured with `git status --porcelain -- src tests` = empty. (source: SWEEP#finality (Run 1 + Run 2, checker W-3))
