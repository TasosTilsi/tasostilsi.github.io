<objective>
Deliver REV-25 (the mobile-native platform pack) and REV-24 (the avatar removal) — the two changes that make the phone stop feeling like "a website in a browser", plus the small content deletion the user asked for explicitly.

**REV-25 is one coupled change, not three.** `env(safe-area-inset-*)` resolves to `0px` unless `viewport-fit=cover` is declared (WebKit's rule), so the meta and the CSS are inert apart from each other. Measured on the current build, every route emits TWO `name="viewport"` tags — the data-file line (`…, shrink-to-fit=no`, rendered at `src/app/layout.tsx:104`) and Next's own default (`width=device-width, initial-scale=1`) — so the phone is running on an undefined multi-tag tie-break. The fix is to emit exactly one, from Next's typed `viewport` export.

**The height lock needs one line beyond what CONTEXT D-06 says** (UI-SPEC §8 UNRESOLVED-D3 records this as a resolved, in-scope deviation): `height: 100%` + `overflow: hidden` cannot kill the gap-after-footer, because `body` is `flex flex-col h-full` (`src/app/layout.tsx:129`) and the shell is `h-dvh` (`explore-shell.tsx:65`) — with a static height on `html/body` the shell is a `flex-shrink: 1` item that can never grow into the space a retracted URL bar frees, leaving exactly the strip the user reported. Adding `height: 100dvh` makes all three the same dynamic number. `height: 100%` stays FIRST (fallback + two pinned regexes).

**Placement is load-bearing, not style.** The pack is appended at the very END of `globals.css`, after the reduced-motion guard block. `tests/explore-visuals.test.mjs:445-452` (twin at `:530-540`) defines the "motion region" as the span from `@keyframes explore-panel-in` (line 595) to the FIRST `@media (prefers-reduced-motion: reduce)` (line 681) and asserts every opening-brace line in it contains `.explore-shell`; the safe-area block needs a `@media (min-width: 640px) {` line, whose selector contains no `.explore-shell` → RED if placed inside that span. `tests/credentials-panel.test.mjs:373` additionally asserts exactly ONE reduced-motion query in the file (verified: 1 today), so the pack may add none. Appending after the guard leaves the region untouched and satisfies both pins.

**File count note for the checker:** 6 files — within the ≤10 heuristic. `explore-header.tsx` and `explore-status-bar.tsx` are deliberately NOT modified: the CSS selector out-specifies the utilities ((0,1,1) vs (0,1,0)) so the header's px-based geometry pins (`tests/explore-header.test.mjs:118-168`) stay untouched, which is also the cleanest proof of "untouched".
</objective>
