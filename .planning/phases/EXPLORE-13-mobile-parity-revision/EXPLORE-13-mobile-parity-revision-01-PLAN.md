<objective>

**Why this is not just "delete `hidden md:flex`".** The gate is one of six `<md` dependencies in the arc path, all verified in the working tree:

| # | Site | Current text | Effect below md |
|---|---|---|---|
| 1 | `experience-section.tsx:134` | `hidden md:flex md:flex-col` | phones never see the arc **or the controls inside it** (the user's "buttons missing") |
| 2 | `experience-section.tsx:132` | `gap-4 md:grid md:h-[calc(100dvh-14rem)] md:grid-cols-[2fr_3fr]` | no base display mode → `gap-4` is inert |
| 3 | `experience-section.tsx:258` | `md:col-start-1 md:row-start-1` | layers are in flow at <md — **stays as-is**, it is what makes the five entries readable |
| 4 | `use-timeline-progress.ts:204` | `if (!mdMedia.matches) return;` | `derive()` never runs → markers unpositioned |
| 5 | `use-timeline-progress.ts:329` and `:348` | `if (!window.matchMedia('(min-width: 768px)').matches) return;` | `goToRole` and the arrow keys are dead |
| 6 | `explore-panels.tsx:140-141` | `md:col-span-2 md:h-[300vh]` + `md:sticky` | no scroll range below md → progress is structurally pinned at 0 — **stays as-is** (CONTEXT/D-06 boundary; UI-SPEC §1.2 line 62 and §11 both pin the sticky range as untouched, so `tests/explore-sweep.test.mjs:100-117`'s `md:`-prefix row stays green) |

Sites 4-6 mean the `<md` arc can only ever be a **rest-state** arc unless the step becomes a discrete index change — which is exactly UI-SPEC RESOLVED-D1 (four pins). Retiring site 1 without sites 4-5 ships a visible but dead arc; retiring site 4 without gating the layer loop deletes four of the five CV entries from the phone. All three moves are one atomic change.

**Why the `<md` step must FEED the derivation (the revision-2 correction).** Retiring the early return is not sufficient for "the focal marker moves to the stepped-to entry" (CONTEXT D-01, SPEC REV-23 acceptance, UI-SPEC §3.1e). The dots' position and emphasis are written **only** by the hook — the dot span is `data-timeline-dot="true" aria-hidden="true" style={{ opacity: 0 }}` (`experience-section.tsx:166-171`) and nothing in JSX positions it. So a step that only calls `setActiveIndex(target)` changes the counter, the label's type/colour class (`:186-191`) and the dot's size class (`:161-163`) — but the enlarged dot sits at its **rest angle** (θ = 180 − i·45) while entry 0 keeps the focal point. Two further facts close the trap: `continuousIndex(progress, roleCount)` (`timeline-geometry.ts:101`) reads `progress = computeProgress(rel, range)` (`:92-95`), which is `0` for `range <= 0` — the `<md` resting state — and where the `<md` wrapper/stage natural heights differ at all (`range > 0`) the mount pass clamps `progress` to `1`, which would park the **last** entry at the focal point. The `<md` derivation input must therefore be the stepped index itself, explicitly, and the derivation must be re-run when it changes.
