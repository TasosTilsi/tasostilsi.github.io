<objective>
Promote the explore experience to the primary landing and move the CLI terminal to /cli as a pure path-rename with zero behavioural change — test-first, then one atomic implementation unit.

Ordering is TDD and mandatory: Task 1 writes and RUNS the failing acceptance suite (`tests/route-swap.test.mjs`) against a fresh build of the CURRENT tree and commits it as `test(phase-12): …`; only then do Tasks 2 and 3 edit implementation files. The observable red must exist on record before any implementation edit, and the red causes must be the missing behaviour (CLI at `/`, no `cli.html`, links still at `/explore`, no chip) — not a broken test.

**Why the implementation is one unit.** In the Next.js App Router two routes resolving to the same URL path are an error, so while both `src/app/(main)/page.tsx` and `src/app/(home)/page.tsx` exist the tree has two providers of `/` and `npm run build` fails. The route move and the six cross-surface link rewires therefore land together in Task 2 (RESEARCH R-1); the tree is never left with a half-landed rename.

**Locked decisions implemented here, not re-litigated:**
- **D-01** — the CLI moves by a byte-identical file move to `src/app/cli/{layout,page}.tsx`, NOT a route-group rename: a route group's folder name is excluded from the URL path, so renaming `(main)` to `(cli)` would leave the CLI at `/`. The landing uses a `(home)` route group (`git mv src/app/explore "src/app/(home)"`) so the before-paint theme script's blast radius stays exactly one route while the URL stays `/`. This is the UI-SPEC §10 PLANNER-CHOICE; the outcome it demands (route-scoped script, no inheritance of the CLI's h-screen wrapper) is what the `(home)` group preserves.
- **D-02** — the root layout keeps GA + JSON-LD + viewport and is NOT edited for metadata; the landing carries explore branding and `/cli` carries CLI branding.
- **D-03** — the link targets and the status-bar `cli` new-tab chip, exactly as pinned by UI-SPEC §2.3/§3.1/§5.

**Declared 6th link site (deliberate, not scope creep).** SPEC/CONTEXT enumerate five link sites. Repo evidence (RESEARCH §3.6, R-9) found a sixth: `src/app/not-found.tsx:104-110` renders `<Link href="/">` with the visible label **"Return to Terminal"**, and `output: 'export'` emits `out/404.html`, which GitHub Pages serves for every unknown path — including the newly deleted `/explore`. Left alone it would send a lost visitor to the explore page while promising the terminal. It is rewired in Task 2 and pinned as composite leg 6, under the SPEC's own acceptance wording ("all cross-surface links … verified navigable") and the cross-surface-links discipline.

**File count note for the checker (RECORDED DEVIATION — flagged in the frontmatter).** 15 paths are listed: 1 new test file, 4 new route files, 4 deletions of the two old route trees, 5 link-site files and 1 constants module. This exceeds the 10-file heuristic by design and cannot be reduced without breaking the build between commits (R-1): the blast radius of a route rename is a fixed enumerated list (RESEARCH §2.2/§2.5 counted it), and every implementation edit in this plan is 1-3 tokens — 5 href/navigate values, 1 constant value, 1 new constant, 2 component edits, 2 moved route pairs. The deviation is recorded as a YAML comment in this plan's frontmatter, not left unflagged.
